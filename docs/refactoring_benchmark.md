# リファクタリング：性能と互換性の検証

## 変更範囲

番号付きスクリプトの順序と照合規則を維持し、共通処理を役割別に分離した。

- AST：ソースの先頭を繰り返しデコードせず、改行位置の索引で行番号を求める。
  メソッドとコメントの情報をTree内で保持し、Parserはスレッドごとに再利用する。
- コメント照合：同じファイルの正規化結果を再利用する。閾値と同点時の選択規則は維持。
- 来歴検証：ファイル読み込みを実行内で共有する。キャッシュのキーはリポジトリ・パス・版、
  上限は128項目。別の実行には持ち越さず、読み込み失敗もキャッシュしない。
- Git認証：`gh auth token`をGit操作ごとに実行せず、プロセス内で再利用する。
  `GH_TOKEN`と環境変数は呼び出しごとに読み、トークンをファイルや測定結果に保存しない。
- 環境情報：パッケージの版を`pip show`の反復実行ではなく`importlib.metadata`から取得する。

## 固定サンプルの計測

2026-10-31、同じローカル環境・Python 3.9.6で計測した。
`scripts/26_benchmark.py --repeat 3`の中央値。対象は関数ID
`1134 / 12982 / 18082 / 24804 / 34583`の5ソース
（75,892 / 17,521 / 2,880 / 49,475 / 138,431 bytes）。

| 処理 | 旧版 | リファクタリング後 | 比率 |
| --- | ---: | ---: | ---: |
| AST解析とメソッド・コメント情報取得 | 335.4 ms | 77.3 ms | 約4.3倍 |
| コメント照合 | 261.4 ms | 71.6 ms | 約3.7倍 |
| Git環境準備10回 | 236.7 ms | 0.414 ms | 約572倍 |

Git環境準備は認証情報取得後のウォーム状態での値。初回のCLI起動時間を含まない。
ASTとコメント照合は旧新版の結果ハッシュが一致した。ソースのハッシュも一致している。
この倍率は個別処理のもので、Git履歴探索を含む通し実行の倍率ではない。
バックグラウンド実行やOSのファイルキャッシュもあるため、時間は参考値である。

全4,961コメントの本文検証は、旧版の単回測定9.42秒に対し、新版では
1.70 / 1.03 / 1.05秒（中央値1.05秒）、いずれも0 badだった。
旧版と新版の反復数が異なるため、厳密な倍率比較には用いない。

`03_locate.py --all`のログでは旧版5.2分、新版3.5分だった（各1回）。
候補選択の揺れと実行環境の影響があるため、通し実行の厳密な倍率とは扱わない。

## 旧版に存在する再現性の問題

変更前の`reproduce.sh`だけでも、既存の検証済みCSVに対して26行が変化した。
commit付きの件数は4,961件のままだが、`19831 / comment_id 0`が別ファイルへの
`relocated`対応となり、本文検証は4,960 ok / 1 badになった。
`24_consistency.py`はOKであり、件数・構造の一致だけではこの誤対応を検出できない。

候補集合の同点選択や別コピーへの対応には、リファクタリング前から結果の揺れがある。
`PYTHONHASHSEED`だけを固定しても、`rg`の検索結果順が変わると、
ヒット数同点のファイルの優先順位が変わる。検索結果の順序も揃えた比較では
旧新版が一致したため、この問題は検索・候補選択の安定化が必要である。
今回の互換性確認と切り分けるため、照合方針を変える修正は行っていない。
通し再実行の生成物をそのまま正解として採用せず、公開成果物は作業前の検証済み状態を維持する。

新版の通し再実行でも4,961件中同じ1件が本文検証に失敗した。
作業前に対して27行、旧版再実行に対して20行のCSV差分があり、
通し再実行の完全一致は確認できていない。候補選択の安定化と、検証失敗時の
終了コードの修正は別課題として記録した。
