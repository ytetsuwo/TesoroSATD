# 再現性と誤対応の修正

## 原因と変更

1. `rg`の並列検索結果が到着した順序で、ヒット数同点のファイルの優先順位が変わっていた。
   検索結果を並べ替え、候補をヒット数の降順・パスの昇順で評価する。
2. 別ファイル探索はコメント周辺のコードも照合し、本文行数だけで範囲を決めていた。
   ASTコメントノードの本文に限定し、必要な非空行を収集して、間の空行も範囲に含める。
   行末コメントより前のコードは照合に使わない。
3. `05_verify.py`は失敗を表示しても終了コード0を返していた。
   全件本文検証、標本のtext / blame / showのいずれかが失敗すれば1を返す。

`19831 / comment_id 0`は実ファイルを確認し、手動対応付けに登録した。

- リポジトリ：`duarterafael/Conformitate`
- パス：`MainProject/use-3.0.7/src/main/org/tzi/use/uml/sys/soil/MOperationCallStatement.java`
- コメント：82〜86行、`getObject()`の直上のTODO / @returnブロック
- SHA：`c1da7401c62a6d8c8d5046ef6aa03cf0f9304e89`

HEADの手動対応付けでは、以前の`at_commit`を削除する。過去のスナップショットを
誤って参照しないためである。同文の別コピーが常に正しい来歴とは限らない点は、
順序の固定や本文検証だけでは解決できない。
